## 最小验证清单（未知-未知象限 → 可验证实验）

### A: 多导出加载行为（v0.1 发布前）
1. 构建与正式 dist/ 结构相同的包，根入口只具名导出两个插件函数;
2. 两函数分别注册唯一工具和可观察 hook;
3. 通过 OpenCode 包加载路径加载（不是源码 import）;
4. 成功信号: 两函数各执行一次、两工具均出现、hook 均生效且无重复注册;
5. 记录加载顺序; 一个函数初始化失败时对另一个的影响。

### D: Bun 缓存与精确版本
1. 隔离配置与缓存中准备两个行为可区分的精确版本;
2. 依次固定版本一 → 升级版本二 → 回退版本一;
3. 每次重启记录实际加载版本、缓存目录、工具标识;
4. 成功信号: 配置中的精确版本决定加载结果，不受旧缓存/同名新版本干扰。

### F: 启动阶段模型读取
1. 插件初始化期间调用 client.config.providers();
2. 记录 TSGW provider、models 字典、逐模型状态字段（不记录 key/完整 options）;
3. 覆盖: provider 存在/缺失/超时/异常、models 缺失或格式异常;
4. 成功信号: 启动生命周期允许有界探测，确定哪些字段可用于"声明支持/启用"判断。

### 三层模型语义（注册行为）
按 docs/design/registration.md「三层模型语义」5 条逐项验证。

### 发布物烟雾验证（可与 A 合并）
检查 tarball 文件白名单、根入口导入、运行时依赖解析、声明文件——避免本地源码加载成功但 npm 产物失败。

## 禁止事项（施工红线）

- 不得静默改变既有插件行为（ts_search 的 chat.params、双路协议、输出契约；ts-mark 的参数语义与机械验证矩阵等）; 行为变更必须先重新整理设计并确认。
- 不得在迁移期同时保留本地入口与包内同名插件（双加载）。
- 不得用 @latest 发布策略; 包内锁版本。
- 不得绕过 strict 编译门槛。
- 不在设计文档未经确认前发布包或修改本机配置。
